#onnxruntime
Существует библиотека для инференса моделей под названием ONNX Runtime от Microsoft. Она легковесна и позволяет эффективно запускать инференс на разном железе. Работает с обменным форматом ONNX.
Запуск выглядит следующим образом: 
экспортируем модель в ONNX формат, 
конвертуруем данные в nympy массив
загружаем модель с помощью  onnxruntime и запускаем инференс
Никакого torch и других пакетов весом в несколько Гб.
Надо обратить внимание на то, что существуют несколько версий библиотеки оптимизированных для работы с разным железом и в разных окружениях. Пакеты  установки названиями называются по разному. Импортируются к коде они под одним именем. то есть установить два разных пакета в одно окружение нельзя.
#TensorRT
Вторая библиотека, которая сегодня будет использоваться, — это TensorRT от Nvidia. Она предназначена для ускорения инференса на GPU от Nvidia.
Сегодня мы объединим обе библиотеки: запустим инференс в ONNX Runtime, используя возможности TensorRT без полной конвертации в его формат. Это возможно благодаря механизму провайдеров в ONNXRuntime.
#providers
Как уже было сказано, ONNX Runtime существует в нескольких версиях. Например, для Nvidia GPU есть специальный пакет Nvidia GPU. Также есть и другие версии — например, пакет для запуска на устройствах Intel с использованием OpenVINO. Есть возможность дополнительно ускорить работу этой библиотеки, совместив её с TensorRT, — именно это мы и попробуем сделать.

#error
Теперь попробуем запустить инференс нашей конвертированной ResNet‑18. В качестве входных данных используем numpy массив случайных чисел размером с картинку — и получаем ошибку.
По тексту ошибки видно, что система не смогла использовать провайдер *TensorRT Execution Provider*, который мы хотели бы  задействовать так как у нас есть GPU. И все вычисления выполнялись на центральном процессоре. Тем не менее результат был получен.
Дело в путях.  Вот эти два файла ("libnvinfer.so", "libnvonnxparser.so"), фактически это и есть TensorRT. 
 ONNX Runtime ищет файлы TensorRT  в системных каталогах и не находит их там.
Потому что они установлены через pip в Site-packages директорию.
Как исправить эту ситуацию? Есть два способа:
Добавить путь к каталогу, в котором находится TensorRT в LD_LIBRARY_PATH, и делать это каждый раз при запуске блокнота.
Установить библиотеку в системный каталог.
В случае с Colab или другим контейнером проще выбрать второй вариант. 
После установки снова запустим Resnet.
Теперь, в списке провайдеров, использованных в сессии, появился TensorRT. То есть код выполнился на GPU с использованием TensorRT.

# cuda libs
Какие ещё проблемы могут возникнуть при запуске? Иногда ошибка возникает из‑за несовместимости версий CUDA. Дело в том, что разные библиотеки могут использовать разные версии CUDA. Например, Onnxruntime  ссылается на системную CUDA — это хорошо, а PyTorch в некоторых версиях может иметь собственную запись в RPATH, которая ссылается на локальную версию. 
Так что если возникает непонятная ошибка связанная с версией CUDA нужно убедиться, что версии совместимы между собой.
Например в нашем случае, TensorRT 10.1.6 скомпилирован под CUDA 13, а фактически используется CUDA 12. Но благодаря обратной совместимости эта проблема не вызывает сбоев.
Если проблема всё‑таки возникла, то было бы  полезно посмотреть, какая именно версия CUDA используется при запуске.
Вот скрипт который помогает это сделать: он запускает инференс и проверяет, какая версия библиотеки фактически подгружена, — на основе этой информации можно исправлять ошибки.

#summary
Суммируем информацию, которую мы использовали:
ONNX Runtime может работать с рядом провайдеров. Некоторые из них требуют установки специального пакета(openvino). В случае TensorRT мы устанавливаем пакет для GPU и используем его с отдельно установленным tensorRT.
Важно учитывать совместимость этих пакетов между собой. На сайте ONNX Runtime есть документация, где указано, какие версии TensorRT подходят для каких версий ONNX Runtime и с какими версиями CUDA они совместимы.
Независимо от того, какой пакет был установлен, запуск всегда выполняется через импорт onnxruntime. Поэтому в одно окружение нельзя установить несколько разных провайдеров.

#slide_cuda_path
Библиотека CUDA может быть установлена в разных местах: как в системных каталогах, так и в виртуальном окружении. Некоторые пакеты, такие как TorchVision, приносят с собой определённую версию CUDA, и могут содержать путь к этой конкретной  версии CUDA.
Информация о версии CUDA в драйвере видеокарты (nvidia-smi), — это просто максимальная версия, с которой он может работать.Это не означает что в системе установленна именно она
Как происходит фактический поиск библиотек:
Если внутри библиотеки установлена переменная RPATH, поиск сначала проходит по ней. В некоторых версиях TensorRT она указывает на CUDA внутри виртуального окружения, а не в системе.
Если такой переменной нет, используется системная переменная LD_LIBRARY_PATH, куда можно добавитьпуть к которую мы планируем использовать.
Далее может задействоваться rpath внутри файлов, и только потом происходит поиск в системных каталогах.
Основной способ исправить ситуацию, если что‑то не подгружается, — задать пути в LD_LIBRARY_PATH.
#installation
Есть два варианта установки:
Установить TensorRT в систему — тогда ONNX Runtime сразу её увидит.
Установит оба пакета через pip в виртуальное окружение и вручную прописываем в LD_LIBRARY_PATH пути к TensorRT и, при необходимости, к cuDNN.
После этого:
импортируем ONNX Runtime (без указания GPU);
указываем нужный провайдер — в данном случае TensorRT;
подаем данные на вход.
Если в списке провайдеров, использованных в сессии, числится TensorRT, значит, вычисления шли на нём.
