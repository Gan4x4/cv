#Detection_task
Детекция — это задача поиска области на изображении, в которой находится объект.
Область обычно задается ограничивающим прямоугольником (bounding box). В классической постановке задачи стороны прямоугольника параллельны сторонам изображения.
Задача усложняется тем, что:
* объекты могут принадлежать к различным классам,
* объектов каждого класса на изображении может быть несколько или не быть вообще.


#one_object
Начнём с простой ситуации: на изображении точно присутствует только один объект одного класса.
Прямоугольник однозначно задается координатами двух противоположных вершин.
Поиск координат вершин (чисел) — это задача регрессии.
Простым решением такой задачи может быть изменение количества выходов последнего слоя на 4 и замена функции потерь на MSE.
Чтобы не зависеть от разрешения изображения, координаты удобно предсказывать в процентах от длины и ширины изображения; для этого выходы модели нормализуют (например, добавив сигмоиду).
#multiclass
Усложним задачу: объект по-прежнему один, но он может принадлежать к разным классам.
Задачу классификации мы решать умеем.
Мы можем добавить к нашей базовой модели (backbone) классификатор (голову), который будет решать задачу классификации.
Чтобы учить классификатор, нужна функция потерь на базе кросс-энтропии.
А чтобы обучить модель, которая одновременно решает задачу регрессии и классификации, нам придется объединить две разные функции потерь.
Базовое решение — это их взвешенная сумма, коэффициенты перед разными loss — это гиперпараметры, которые надо подбирать.
Возможно делать это автоматически, существует целое направление в машинном обучении (Multi-task learning), направленное на то, чтобы обучать веса для компонентов loss вместе с моделью.
#multi-object
Как быть если объектов может быть несколько? Если объектов много, то модель должна выдавать несколько  предсказаний, то есть иметь несколько выходов.
Но мы не знаем заранее, сколько объектов может быть на изображении.
Потенциально проблему можно решить двумя способами:
* Делать предсказания для максимально возможного количества объектов.
* Применять модель, детектирующую один объект внутри скользящего окна.
Проблема скользящего окна в его колоссальной вычислительной неэффективности. Так как мы не знаем размеры объекта, то придется перебрать не только все возможные положения окна, но и размеры. Это десятки тысяч запусков даже на небольшом изображении.
Большинство моделей для детектирования так или иначе пытаются использовать и оптимизировать эти подходы.
И сейчас мы обсудим основные подходы которые для этого применяются.
#R-CNN: Авторы сначала использовали эвристику, которая находила «регионы интереса» (RoI) на изображении, таким образом снизив количество запусков модели до ~2K.
В последующих версиях эвристику заменили на нейросеть, которая ищет RoI уже на карте признаков, а затем вторая модель классифицировала объекты внутри и уточняла координаты RoI. Такие архитектуры называются двухступенчатыми.
#One_Stage: В ряде моделей отказались от двухступенчатого подхода.
На картах признаков разного масштаба задается фиксированное множество прямоугольников с разным соотношением сторон (anchors box).
 Модель предсказывает смещение и класс для каждого прямоугольника. Существенно, что смещение, которое может предсказать модель, ограничено, так как нет смысла сдвигать bounding box на место соседнего.
 Предсказаний требуется сделать намного больше (~10K), зато не требуется обучать дополнительную модель для поиска RoI. И модели на базе такой архитектуры (YOLO / SSD / RetinaNet) работают быстрее, чем двухстадийные. И именно они применяются для задач детектирования в реальном времени.
#anchor_free
Количество и размер anchor — это гиперпараметр, который нужно подбирать.
Можно исходить из того что центр объекта может находиться в любой точке на карте признаков, а предсказание размеров ограничивающего прямоугольника полностью поручить нейросети. Так работают anchor-free детекторы, например FCOS.
#transformers :
Во всех перечисленных выше случаях модели делают тысячи предсказаний, что на порядки больше, чем реальное число объектов на изображении. Это означает, что:
 - большая часть предсказанных bounding box должна иметь класс «фон»,
- и сильно накладываться друг на друга.
В моделях на базе сверточных сетей уменьшить это количество сложно, так как модели работают с локальными признаками и предсказывают каждый bounding box независимо, не используя глобальный контекст изображения.
ViT-архитектуры снизили число предсказаний до нескольких сотен благодаря механизму внимания, использующему глобальный контекст изображения.
Основная идея (DETR) состоит в том, что в ходе обучения обучается фиксированный набор векторов (100–300), который используется как Query в слое self-attention. На выходе получаем набор токенов, каждый из которых кодирует один bounding box.
Благодаря механизму внимания, который позволяет учитывать взаимосвязи между всеми объектами одновременно, предсказанные bbox имеют намного меньше наложений, чем в моделях на базе CNN.
#common_scheme
Рассмотрим общую схему для детекторов, основанных на свертках:
*  Изображение подается на вход сверточной модели, и на выходе получаем карту или несколько карт признаков.
* На карте признаков ищутся области, в которых потенциально могут находиться объекты. Для этого может использоваться модель или эвристика (R-CNN), заранее определенный набор прямоугольников (anchor box) или только центры объектов (FCOS).
* Следующий блок получает на вход признаки вместе с координатами областей и предсказывает: класс объекта, смещения для координат и, в некоторых случаях, число, обозначающее уверенность в предсказании.
* Полученные предсказания (десятки тысяч) фильтруются. Для отбрасывания дубликатов используется алгоритм Non-Maximum Suppression (NMS).


#NMS
Алгоритм:
1. Выбирается прогноз с наибольшей уверенностью(confidence score). Этот bounding box переносится в итоговый список.
2. Для выбранного bounding box считается IoU с каждым из оставшихся bounding boxes. Если IoU больше порога — bounding box удаляется (считается, что это bounding box для того же объекта, который добавлен в итоговый список).
Шаги 1–2 повторяются, пока список возможных bounding boxes не опустеет.
Предсказания для разных классов обрабатываются независимо.
NMS может удалять истинные bounding boxes для близко расположенных объектов, требует confidence score и подбор порога. Кроме того, для десятков тысяч bounding box эта операция достаточно медленная.
Поэтому в современных моделях пытаются избавиться от этой операции, по крайней мере, в режиме вывода.
Способы сделать это связанны с тем как модель учится, поэтому разберемся с функцией потерь для реальных детекторов.
Базово Loss для детектора — это взвешенная сумма loss-функций для классификации и регрессии. Но в регрессионном компоненте учитываются не все предсказанные bounding box, а только те, которые наилучшим образом пересекаются с GT.
